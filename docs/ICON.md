# 图标说明 · 勘读 / KanRead

图标的**含义、来历、加工方式与复现步骤**。

---

## 1. 含义

> **一条平直的横画表示"被核定的文本"，右下一点表示"句读"，即阅读与精读。**

这枚图标不是"画一件器物"，而是用**两个抽象符号**指代"勘"与"读"这两件事：

- **横画＝勘的准线。** "勘"是拿一条基准去逐字核定文本（校勘、勘误都是这个动作）。
  这条横画**刻意不按毛笔的书写方式**：它不是书法里的一笔，而是界画的一条准线——
  平直、两端圆头，正好是"用来对齐、用来比对"的样子。它整帧降采样后被压成一根直条
  却看不出失真（见 §3 的加工表），正因为**它本来就是直的**。
- **墨点＝读的落点。** 句读是阅读留下的痕迹；点落在横画右下方，既像一句读标记，
  也像"核到这一行，就停在这里"——正对应这个应用"每句结论都要对得上原文某一行"的底线。

它是抽象标记，不是具象插画，因此在极小尺寸下也不会出现"糊成一团看不出是什么"的问题
（它本来就不表现具体物体）。

| 元素 | 颜色（成品） | 含义 |
| --- | --- | --- |
| 圆角底 | `#28654e` `(40,101,78)` | 一页纸的底色；同时是应用主色（界面 `--accent` 同族） |
| 横画 | `#e9eee5` `(233,238,229)` | **被核定的文本，也是勘的准线**。刻意平直、两端圆头，不采用毛笔笔法 |
| 墨点 | `(13,30,24)` | **句读**：阅读与精读的落点。位置在横画右下方，像一句读标记 |

## 2. 来历与授权

- **底图由设计者用生图 AI 生成**（不是本项目画的，也不是本项目手绘的几何图形）。
  原稿已归档在 `assets/icon-master.png`（1254px，透明通道），见 `assets/README.md`；
  成品由 `scripts/adopt_icon.py` 从母本重出（取母本 → 预乘缩放 → 打包，**不重画形状**）。
- 因此图标**不是**本项目的原创几何图形。来历保留在此，是为了让使用者能看清这一点。
- 名称与标识**不随代码许可证授权**：见 `legal/BRAND.md`。

## 3. 加工做了什么（`scripts/build_icon.py`）

底图是 1254×1254 的生成图，直接当图标用会有四个问题，脚本逐个解决：

| 问题 | 处理 |
| --- | --- |
| 带一层近白背景，放进深色任务栏就是一个白方块 | 按颜色分离"圆角底 / 横画 / 墨点"，其余透明 |
| 圆角边缘带压缩噪点与锯齿，缩到 16px 变成毛边 | 量出圆角半径（15.5%），用 4× 超采样重画圆角矩形 |
| 横画是手绘感的有机形状，整帧降采样会被压成一根直条 | **量出每一列的上下边** → 平滑 → 重画多边形 + 两端圆头 |
| 墨点与底色亮度只差 11%（对比度 1.94:1），16px 下消失 | 加深到 `(13,30,24)`（2.95:1），位置与直径仍用底图实测值 |

尺寸策略：ICO 含 16/24/32/48/64/128/256 七档，条目内放 PNG。

## 4. 复现与校验

```powershell
# 1) 重出图标成品（母本已归档在 assets/icon-master.png，不带参数就用它）
.\.venv\Scripts\python scripts\adopt_icon.py
# 2) 登记资源哈希（图标是仓库资源，必须入清单）
.\.venv\Scripts\python scripts\license_inventory.py
# 3) 重新编译带图标的启动器（/win32icon，编译后再独立校验产物）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-launcher.ps1
# 4) 契约测试
.\.venv\Scripts\python -m pytest -q tests/test_icon.py
```

母本与归档说明见 [`assets/README.md`](../assets/README.md)；`scripts/adopt_icon.py` 也接受
直接指向新母本（`... adopt_icon.py <新图.png|.ico>`），并会把新图写回 `assets/`。

- `scripts/icon-preview.png` 是多尺寸预览（不入库）：**改完必须打开看一眼小尺寸**。
  `--compare` 另出 `scripts/icon-compare.png`（照搬版 vs 美化版并排）。
- `scripts/check-exe-icon.ps1` 校验编译产物里真有 `RT_GROUP_ICON`：`csc /win32icon` 失败时
  只给警告、仍返回 0，不校验就会产出"没有图标的 exe"，而这只有用户双击时才看得见。
- 缩放实现的两个坑（`adopt_icon.py` 与 `build_icon.py` 的缩放函数，别改成 LANCZOS）：
  ① 直接缩 RGBA 会被透明像素的 RGB=0 拖出黑边，必须走预乘；
  ② **预乘之后不要"除以 alpha 还原"**——半覆盖像素的 RGB 会被除以 0.75 之类的 alpha、
  颜色被提亮成浅绿，于是每一档都围着一圈发白的糊边，小尺寸下整块看不清（2026-09-20 实测：
  16px 档边缘出现 `(190,150,…)` 这类浅色，换成按预乘合成后恢复成 `(36,95,73)`）。
  正确做法就是 `C = C·α + 0·(1-α)`，颜色保持不变、只有不透明度降低。
